# ChainSpot S0–S7 ordered recipe

From the extracted `nctk-stages/` directory, run with Node and npm. The source packet contains the pinned provider source and lockfile. Each `run` creates a fresh isolated fork, installs with `npm ci --ignore-scripts`, invokes native provider gateways, hashes native evidence, and writes a retained Attempt. This is lockfile pinning, not a hermetic/offline guarantee.

```bash
node toolkit.mjs neat --recipe recipes/chainspot-s0-s7.json --specimen golden --until 7 --lanes s4.basketRecovery,s5.globalAssignment,s5-axis-heading
node toolkit.mjs kompoze --recipe recipes/chainspot-s0-s7.json --specimen golden --until 7 --lanes s4.basketRecovery,s5.globalAssignment,s5-axis-heading
node toolkit.mjs crisp --recipe recipes/chainspot-s0-s7.json --specimen golden --until 7 --lanes s4.basketRecovery,s5.globalAssignment,s5-axis-heading
node toolkit.mjs run --recipe recipes/chainspot-s0-s7.json --specimen golden --until 7 --lanes s4.basketRecovery,s5.globalAssignment,s5-axis-heading
node toolkit.mjs tidy --recipe recipes/chainspot-s0-s7.json --specimen golden --until 7 --lanes s4.basketRecovery,s5.globalAssignment,s5-axis-heading
node toolkit.mjs compare --recipe recipes/chainspot-s0-s7.json --specimen golden --until 7 --lanes s4.basketRecovery,s5.globalAssignment,s5-axis-heading
```

Use `--specimen alex` consistently in neat and subsequent commands for AlexClark-original.jpg. `--until 3` stops after S3. `--stage 5` selects S5 while executing its necessary S0→S5 prefix; combine it with a named lane whose stage is within that prefix. A changed specimen requires a new neat checkpoint. An exact repeat of run reuses only if all expected native evidence files still hash correctly. `tidy` distinguishes changed source, result freshness, process execution, and human acceptance. `compare` shows A byte inventory, B declared Stage boundary graph, and C Attempt/evidence lineage from the same request. The compiler rejects missing/ambiguous/forward Stage Part producer declarations; the pinned provider's inner Calculation catalog remains native, with actual Tick testimony in PCR.

**Parallel work.** Checkpoints are immutable files `attempts/stages/checkpoints/ID.json`; `neat` prints `checkpointId` and a ready `next` command. Every later command accepts `--checkpoint ID` (full ID or unique prefix); without it the shared pointer `attempts/stages/checkpoint.json` (whatever the last `neat` wrote, possibly another agent's) is used. Either way the request's specimen, lanes and `--until` are checked against what the checkpoint was made for, and a mismatch names both and lists matching checkpoints. By default `neat` closes over the working tree, so another agent's in-progress edit makes the checkpoint stale; the refusal lists each modified/added file and the command to re-run. To pin committed state while others edit, use `neat ... --from-git HEAD` (any commit-ish): the commit is extracted once into `attempts/stages/trees/COMMIT` and that checkpoint reads and forks only from there. `run --fresh` (also `crisp --fresh`) executes a new Attempt even when a verified one would be reused. Run the tracked tests with `node scripts/test.mjs` (a bare `node --test` also collects the test copies inside `attempts/` forks); evidence-backed tests find the latest matching golden Attempt themselves and skip, naming the command, when none exists.

```bash
node toolkit.mjs neat --recipe recipes/chainspot-s0-s7.json --specimen golden --until 3 --from-git HEAD   # prints checkpointId
node toolkit.mjs run  --recipe recipes/chainspot-s0-s7.json --specimen golden --until 3 --checkpoint ID
```

**Parts, not env.** FunctionalGuarantees (`fg/**/*.fg.mjs`) and fork-join implementations (`impl/<slot>/*.mjs`) read only the Part addresses they declare in `reads` and call only the registered `fn.*` Calculations they declare in `calls`, through the run's addressed store (`fg/store.mjs`, an overlay on the provider PxC); an undeclared address or Calculation fails by name. Toolkit data lives at `tk.*` (source intake, gateway captures `tk.stage.<S>.captured`, snapshots `tk.stage.<S>.snapshot`, `tk.source.cropReceipt`), `view.*` (`view.source.background` for every flipbook) and `testimony.*` (`testimony.source.annotation`, `testimony.source.teePoints`), each produced once by a Calculation that declares its inParts/outParts; provider capabilities are `fn.provider.*` (restore, `executeCompiledPlan`, materializers). The full table is in `ports/early/earlyStore.mjs`. Every Calculation call is timed into `stage-output/early/instrumentation.json` (`calculations`, plus the store manifest), never into the receipt.

The baseline S4 invokes pinned axis-local and broad source-shard recovery over the exact S3 snapshot. S5 signed two-direction measures and S6 corrected direct rays run explicitly through the provider gateway for the ordered recipe; provider feature defaults stay OFF. The S5 global-assignment lane runs the pinned exact sparse matcher over only actual fresh ray hits. It maximizes supported pair cardinality and then minimizes the disclosed weighted distance and axis-residual cost, without a distance cutoff. FULL graph coverage requires every S1 badge to have a distinct selected tee; physical acceptance remains UNKNOWN. The S3 treatment branch does not feed the baseline S4 unless a later recipe explicitly selects those outputs. S4 basket proposals leave S2 baskets and downstream base S6 rows unchanged. S7's legacy selected-badge replay re-decodes the JPEG, so it is separately labeled; the optional fresh S6 row+receipt seal supplies heading hypotheses to the existing tracer, with measured crop-frame translation and badge-center checks. With global assignment ON, S6 and S7 consume only selected headings and retain all alternatives in `candidateHits`. S6 straight-top rejection never vetoes a bent S7 route. Native S7 basket outcomes include BBOX entry, not independently accepted owned-pixel arrival.

The optional `s4.singletonPropagation` lane inserts a second S4 gateway before S5. Its first Tick invokes the pinned native recovery builder through a hash-checked isolated export overlay, retaining all pre-winner fits, strict predicates, source cells, and visible-tee duplicate decisions. Its second Tick groups overlapping exact source-cell supports and removes uncontested singleton holes to a fixed point. Persistent singleton conflicts remain explicit and their reduced queues continue to the native rank order; a conflict is not a forced choice. The ON branch uses only post-propagation conditional axes for S5, while the old broad winner-first additions remain comparison evidence. A badge-conditioned pose cannot generate a candidate ray hit for another badge without a refit. In the Alex control, this graph can cover all 18 badges while using far-left/footer fragments and a 1206px tee-badge pair, so graph coverage is not physical recovery.

The progress view is generated from a completed fork and works directly from `file://`, embedding the verified source JPEG and native receipt layers. Its S0–S7 scrubber accumulates observed object pixels, exact tee corners, recovered/inferred geometry, plate hits, top candidates/rejections, and path traces on one cropped-course canvas. After a run, use `node ui/render-board.mjs attempts/stages/ATTEMPT_ID/fork` to regenerate `stage-output/progress.html`; replace ATTEMPT_ID with the printed ID. Open that HTML locally. Source-pixel and receipt hashes are checked before display. A command in each stage card selects that stage's required prefix.
