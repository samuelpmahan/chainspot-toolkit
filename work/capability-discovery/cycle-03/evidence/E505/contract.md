# E505 independent predeclared source-pixel adapter contract

D5 owns this predeclaration and synthetic oracle specification. D6 owns implementation. Candidate source has not been read or run. This is a contract freeze, not technical acceptance or independent image evaluation. Repository remains read only for D5.

## Exact pixel identity

An enabled adapter accepts a real source file plus an expected SHA256 of its exact encoded bytes, an explicitly named full-image frame, an explicitly named crop frame, and a caller-declared integer crop x,y,width,height. Decode through the existing pinned decoder, preserve original width/height and all four decoded RGBA channels, then copy integer rows. Source frame integer (0,0) is the center of the first decoded pixel. The local integer (i,j) refers exactly to full-image (x+i,y+j); no half-pixel origin shift.

Crop x/y are nonnegative safe integers; width/height are positive safe integers; sums and byte counts must be safe and remain inside source dimensions. Exact edge-touching crops and 1x1 crops are valid pixel operations. Invalid/empty/malformed/outside crops explicitly reject or return UNKNOWN without recipe execution, never round, resize, color-convert, premultiply, drop alpha, pad, clamp, clip or create substitute pixels. Preserve hidden RGB at alpha0. Outputs are separate snapshots; caller or downstream mutation must not mutate the decoded source or vice versa.

Retain three distinct SHA256 referents: actual source-file encoded bytes, decoded full-frame row-major RGBA bytes, and copied crop row-major RGBA bytes. Record dimensions, exact crop bounds, decoder identity/dependency provenance, caller expected source hash and verified actual hash. The raw RGBA digest excludes dimensions, so dimensions are separately mandatory; do not conflate source-file SHA, raw-RGBA SHA and materializeComposite's dimension-prefixed imageId. Any expected source hash mismatch must stop before downstream observations, including when an alternate encoding decodes identically. Corrupt/unsupported files and decoder failures remain explicit failures. No unpinned alternate decoder or implicit EXIF rotation path.

## Geometry translation

For every training tee/badge point and station origin, crop position is xPx-x,yPx-y. Preserve finite fractional geometry exactly: do not Math.round/floor/ceil points. HeadingRad, longitudinal t0Px/t1Px, bank widths, dimensions, offsets and edge-search settings are unchanged. Heading π/2 and non-axis heading0.731 exercise translation with rotated sampling axes: the image and geometry are never rotated. All nested frame labels become the crop frame through one explicit transformation.

Known occluder boxes use bboxX-x,bboxY-y, identical bboxW/bboxH and the same inclusive point semantics as existing sources. Preserve fractional, zero-size and partly/fully outside crop boxes without clipping, dilation or omission. A negative local box origin is meaningful. All geometry must declare the correct source frame; mismatched frames, malformed/nonfinite fields, degenerate training and invalid candidate-bank/search settings must not execute the recipe. Outside-full-frame points must reject or report explicit outside-frame UNKNOWN. Points inside source but outside crop can remain exact negative local positions only if support is explicitly insufficient/UNKNOWN; they must never be coerced into the crop.

## Sampling support is separate from crop validity

A valid crop is not proof that every observation is supported. Existing JS profiles sample longitudinal arange(t0,t1,1), fixed normal offsets -30..30 at0.25px and reject sample points unless x>1,x<W-2,y>1,y<H-2; original sampler clamps its bilinear stencil internally. Existing Dev72 samples nearest RGB pixels across five tangent positions -4,-2,0,2,4 for each lane/guard/rail, including edgeDelta2.5, and can report a finite score from partial visibility. Candidate widths below1 are internally maxed to1 by that original source; caller values must stay unchanged and any such seam stay visible. Training generates five poses at segment fractions0.2,0.35,0.5,0.65,0.78 per candidate width. Any adapter support check must cover all requested stations AND learner sample poses, all candidate widths, the source-specific lateral/tangent footprint and known occluder semantics.

An adapter may conservatively reject unsupported support before recipe execution or retain raw unchanged recipe channels with explicit per-request support limitations. It cannot claim complete support merely because center points/crop bounds are in frame, because a finite score exists, or because a source fallback selects a numeric width. No silent padding/clamping is introduced by the adapter. Partial/missing support, all-hidden channels, insufficient station counts, empty bank/training, no paired edge and null/nonfinite diagnostics remain visible. No observed/calibrated width is minted from a raw fallback, first-candidate return, one-sided/interior-only score, or insufficient edge support. Existing localWidth.widthPx remains null/UNKNOWN; semantic identity and calibration remain UNKNOWN; promoted=false.

## Scope and freeze

The existing composition recipe, source vendor files, candidate-bank execution and defaults remain unchanged. Adapter defaults OFF and must require explicit opt-in. No alternate CV, AA muting, renderer inference, automatic geometry/width search, recentering, confidence threshold or production integration.

oracles.json fixes literal RGBA bytes, exact crop outputs/digests and fractional/rotated geometry results. The two PNG sources have different encoded source hashes but identical decoded RGBA hashes. They are exposed synthetic contract fixtures, not an independent real-course corpus. Test malformed/null/nonfinite API and CLI inputs, all crop boundary errors, source mismatch, complete/partial/outside/hidden support, short windows and existing fallback abstention. API shape may differ; review must bind these semantic assertions to actual exported entry points rather than invent a different candidate API.

Predicted falsifier: a near-edge crop leaves finite source channels or a raw numeric fallback while complete sample support is missing. Accepting that as a supported/calibrated width, hiding unsupported samples, modifying pixels, or silently shifting geometry fails this contract. Additional identity falsifier: two differently compressed source PNGs decode identically; an adapter that checks decoded hash in place of expected source-file hash wrongly accepts substitution.

Caller course labels, tee/badge coordinates, regions and occluder boxes are testimony, not physical/semantic truth. Proposed positive/negative controls are proposals until actually executed and inspected; no matched-control success is claimed by this predeclaration. All future tested regions become exposed after their runs and cannot later be described as withheld independent evidence. R506 must be performed only after exact D6 candidate freeze/release; this E505 does not review or approve its own code.
