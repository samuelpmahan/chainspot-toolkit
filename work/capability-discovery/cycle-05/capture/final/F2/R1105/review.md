### A2 — account separately for calls, registry emissions and Calculation logs

The registry key is literally function name plus JSON.stringify(rawArgs), before Part resolution. Ordinary key ordering can change misses. JSON key formation is not a content-hash invalidator for mutable referenced rasters. Approved inputs must exclude undefined/nonfinite/unsupported shapes that could collapse or alias raw-argument keys.

Query registrations declare no outParts. Consequently the outer PartStore content cache does not key/cache these query Calculations: for successful query calls `entry.key` stays null and `entry.cached` stays false, even if the query answer has `emits.cached=1`. Preserve both raw fields. Use returned `emits.computed`/`emits.cached` and the corresponding instrumentation emits to report the local registry-cache behavior. Neither is an internal sample-count or LUM WeakMap hit counter.

Freeze one explicit input-constant strategy. For eight F4 cases, one width and four queries each, the ordinary source-derived expectation is **32 PATH query invocations**. If each fresh store uses one combined raster+mask constant lazily materialized by the first profile call, that adds eight constant Calculation invocations, for **40 Calculation entries**, not32. This is a review prediction, never an observed count. Separate constants/eager materialization/introspection calls change the trace, so freeze them before execution. `store.calls()` is an uninstrumented read of captured logs; a call to the instrumentation query is itself another Calculation and must be accounted for if used.

The existing log/onCall is completion-order: the lazily nested constant completes before the enclosing profile. Its start sequence can therefore be1 before0 in the captured array. Preserve original capture order and each seq/parent/depth/caller/status/emits; any sequence-sorted view must be separately labelled. Do not require falsely monotonic seq in raw completion-order entries or renumber them to hide nesting.

Keep external requested/attempted/completed/failed query trace separate from Calculation entries and from source-derived internal expectations. An unregistered-name failure can occur before a PartStore entry exists; source/hash/preflight failures produce no API call. A native no-pair condition is a completed call, not an exception or NOT_EXECUTED. Preserve partial traces on exceptions. Count actual captured results, not theoretical counts filled into a successful template.

### A3 — freeze a reversible wire schema, not merely a replacer promise

Freeze the final encoder/decoder/error schema before producer admission and cover it with a separately admitted non-CV roundtrip test. Preserve finite doubles exactly, negative zero, NaN, positive/negative infinity, source null, ordinary arrays and object properties, and supported typed-array constructor/length/ordered elements. If missing/undefined properties are promised, distinguish them explicitly; otherwise reject them rather than claim preservation. Use collision-safe tags/a tagged union or an equally explicit escaping rule, and reject malformed/unsupported tags, constructors, lengths or shapes. Do not accept cycles/accessors/sparse arrays/unsupported containers by flattening them.

The existing store canon `plain`/`canonicalJson` is NOT this raw-output codec: it flattens typed arrays and permits JSON's nonfinite-to-null/negative-zero loss. It is acceptable unchanged for its internal source-defined key behavior, but must not serialize the raw trace. Hash exact encoded trace bytes, not a reserialized parsed approximation. Bind both native raw `{value,unit,emits}` and complete instrumentation sidecar bytes, separating nondeterministic timing identity from deterministic value comparison.

Keep source-null profile entries distinct from tagged stationContrast NaN. Loss corridor `rgbLevel` and `hiddenCenter` are Uint8Array; native corridor RGB is already source-rounded and must not be presented as unrounded source RGB. Decoder roundtrip tests need both corridor arrays, allHidden NaN examples, negative zero/null and deliberate tag collisions. These tests may verify wrapper fidelity, never a physical/scientific hypothesis.
